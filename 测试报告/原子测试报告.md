# 原子落盘专项测试报告（v1.4）

测试对象：v1.4 `sms.exe`（`build.bat` 编译，464,384 字节）
测试日期：2026-10-02
测试工具：`测试报告/harness.js` 的 `atomic` 模式（Node 单文件，两个测试）
被测设计：`saveLocked()` 先写 `students.txt.tmp` → flush → 关闭句柄 →
`MoveFileExA(..., MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 原子替换；
任何时刻磁盘上要么是旧的完整文件，要么是新的完整文件。

## 一、测试 A：写负载期间，数据文件的每一份快照都必须完整

**方法**：临时目录 + 1500 条种子数据；4 条并发写循环（每条 = `POST` 新增 + `PUT` 改分）
持续 4 秒；同时一个读取器不间断读 `students.txt`，对**每一份**快照做严格校验：

- UTF-8 `fatal` 解码（切断在多字节汉字中间会立刻报错）；
- 末行必须以换行结尾（写一半被切断会裸奔）；
- 每行恰好 3 个字段（学号,姓名,总分）；
- 总分必须是非负整数且 ≤ 1000000；
- 学号全表唯一（不允许出现半新半旧叠加出的重复）；
- 行数不允许倒退（本测试只增不改量，原子语义下文件只应变长；
  行数变少 = 被截断重写的直接证据）。

**结果**（3 次）：读取器分别读到 **1145 / 1303 / 1544** 份快照，
**零撕裂、零行数倒退**；收尾核对接口条数 = 文件行数、无残留 `.tmp`。

## 二、测试 B：写负载中多轮强杀，文件必须始终保持完整

**方法**：临时目录 + 3000 条种子数据；一个读取器跨越全部轮次持续校验快照；
共 5 轮，每轮"起服务 → 4 条写循环打 700 ms → `TerminateProcess` 强杀 →
读文件校验"，每轮后确认：

- 文件非空、可完整解析；
- 行数 ≥ 3000（种子量，不允许因强杀丢数据）；
- 清理可能残留的孤儿 `.tmp`（从不被读取，重启即消失）。

5 轮跑完后重启服务，核对接口条数 = 文件行数，并验证可继续写入（201）。

**结果**（3 次）：读取器跨轮次分别读到 **1127 / 929 / 914** 份快照，
零撕裂；5 轮强杀后文件均 ≥3000 行完整；重启后接口 = 文件、`POST` 返回 201。

## 三、变异验证：把落盘改回"直接写"，测试必须变红

只改 `saveLocked()` 一处（回到 v1.2 之前的行为：`ofstream` 直接截断写
`students.txt`，无临时文件、无原子替换），其余不动，重编译后跑同一套 `atomic`：

| 测试 | 变异版结果 |
| --- | --- |
| A（写负载读快照） | **第 1 份写后快照即"空文件"**——`trunc` 的瞬间被抓到；读取器当场标红 |
| B（多轮强杀） | **第 0 轮强杀后"末行不完整（写一半被切断）"**——正是原子替换要杜绝的损坏形态 |

从启动到抓红全程 **5 秒**（14:36:44 → 14:36:49）。随后恢复源码、重建、
复跑 3 次全部恢复绿色。**结论：这套测试对"落盘原子性被破坏"是敏感的，
不是永远绿灯的摆设。**

## 四、只读目录的最坏情况（附带验证）

目录设 ACL 拒绝写入后（普通用户双击运行的等价物）：

- 服务能正常启动，`POST` 返回 **201**（内存中生效，接口立刻可见 4 条）；
- 磁盘文件**保持原 3 行不变、无半写文件**——`ofstream` 打不开 `.tmp` 时直接放弃，
  不会留下坏数据；
- 控制台打印：`[警告] 打不开 …\students.txt.tmp，本次修改只保存在内存中。`
- 重启后：未写入的记录丢失（回到 3 条），**旧数据无损**。

即"只读盘"的最坏结果是本次修改不落盘并明确告知，不会腐蚀已有数据。

## 五、裸 exe 行为（无附带文件）

只拷贝 `sms.exe` 到空目录：

- 控制台菜单正常（学号/姓名/总分分行输入，中文提示与对齐正常），
  退出时自动创建 `students.txt`；
- HTTP 服务照常起在 4399，接口可用；
- 缺 `index.html` 时 `GET /` 返回 404 + `缺少 index.html，请将网页前端文件放到程序同目录。`
- exe 只依赖 `KERNEL32.dll` 与 `WS2_32.dll`（已扫描导入表确认无
  VCRUNTIME/MSVCP 引用），拷到没装 VS 的电脑可直接运行。

## 六、结论

1. 原子落盘在所有测试路径下成立：写负载中的每一份快照、强杀后的每一份文件、
   重启后的数据一致性，全部通过；变异实验证明测试能抓住"直接写"回归。
2. 落盘失败的 degrade 路径也是安全的：只读目录下只警告、不半写、不腐蚀旧数据。
3. 唯一记录在案的瑕疵是 `HEAD /` 附带完整响应体（见压测报告第六节），
   与原子性无关，未处理。
