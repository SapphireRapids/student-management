# 测试流程（可复现）

全部命令在仓库根目录执行（Git Bash）。测试工具是 `测试报告/harness.js`，
运行它需要 Node.js（本机 v24.20.0）和**与 harness.js 同目录**的
`sms.exe`、`index.html`——把编译产物复制过去即可，所有测试都在独立
临时子目录里跑，不会碰仓库里的 `students.txt`。

## 一、编译

```bat
build.bat
```

自动定位本机 Visual Studio C++ 工具链（vswhere）并执行：

```bat
cl /nologo /EHsc /std:c++17 /W4 /utf-8 sms.cpp /Fe:sms.exe /link ws2_32.lib
```

`/W4` 零警告。本机 `cl` 默认静态链接 CRT（已用对照实验确认产物只依赖
KERNEL32/WS2_32，无 VC++ 运行库依赖）。

把产物复制到 harness 旁边：

```bash
cp sms.exe index.html <harness.js 所在目录>/
```

## 二、功能冒烟（接口契约逐项断言，约 10 秒）

```bash
node harness.js smoke
```

26 项断言：状态码（200/201/400/404/405/409/204）、三种排序、中文搜索、
`HEAD /`、录入/改/删的完整链路、接口与文件条数一致、无 `.tmp` 残留。
全部通过输出 `ALL PASS`，有任何一项失败退出码为 1。

## 三、压测（每档约 20 秒，顺序跑，勿并行）

```bash
node harness.js stress <秒> <客户端数> <种子条数> <worker数>
```

本次四档（8 客户端 × 15 s）：

```bash
node harness.js stress 15 8 500 1
node harness.js stress 15 8 2363 2
node harness.js stress 15 8 4599 1
node harness.js stress 15 8 4599 2
```

负载配方：40% 列表 / 20% 搜索 / 20% 新增 / 10% 改分 / 10% 删除；
每请求新建 TCP 连接 + `Connection: close`。404/409 为预期码不计错误，
只有网络层失败计错误。跑完自动核对接口 = 文件、无 `.tmp`。

## 四、边界场景

```bash
node harness.js edge         # 120 连接突发 + 5 空闲连接 + 3 个半截请求（约 90 秒）
node harness.js malformed    # 1.5MB 超大头 / 非 JSON / 错误方法 / 错误路径 / chunked
```

空闲连接与半截请求都带 10 秒级等待，`edge` 跑完约一分半，属预期。

## 五、原子落盘（约 40 秒，两个测试）

```bash
node harness.js atomic
```

- 测试 A：1500 种子，4 条写循环 + 全程读快照严格校验，4 秒；
- 测试 B：3000 种子，5 轮"写 700 ms → 强杀"，每轮后校验文件。

通过标准：读取器快照数 > 阈值、零撕裂、每轮强杀后 ≥3000 行、
重启后接口 = 文件且可写。退出码 0 为全绿。

## 六、变异验证（证明测试有牙齿，每次改动 saveLocked 后建议做）

1. 备份：`cp sms.cpp /c/Users/Sapph/AppData/Local/Temp/sms.cpp.bak`
2. 改 `saveLocked()` 为直接写原文件（去掉 `.tmp` 与 `MoveFileExA`，
   即 `std::ofstream ofs(g_dataFile, trunc)` 直接写）；
3. `build.bat` 重建，复制新 exe 到 harness 目录；
4. `node harness.js atomic` —— 应当**几秒内变红**（抓到空文件或末行撕裂）；
5. 恢复：把备份拷回 `sms.cpp`，重建，`git diff` 必须为空；
6. 复跑 `node harness.js atomic` —— 应当恢复 `ALL PASS`。

## 七、只读目录最坏情况

```bash
mkdir ro && cp sms.exe ro/ && printf 'RO1,甲,100\nRO2,乙,200\nRO3,丙,300\n' > ro/students.txt
MSYS_NO_PATHCONV=1 icacls ro /deny "$(whoami):(WD,AD)"   # 不加 MSYS_NO_PATHCONV 会被 Git Bash 篡改 /deny
node harness.js ro ro                                   # 日志自动放目录外
MSYS_NO_PATHCONV=1 icacls ro /remove:d "$(whoami)"       # 测完恢复权限
rm -rf ro
```

预期：服务能起、`POST` 返回 201、磁盘文件不变、控制台打印落盘警告、
重启后新记录丢失但旧数据无损。

## 八、进程资源

服务起来后（任意模式），另开一个终端：

```powershell
Get-Process sms | Select-Object Id, @{N='Threads';E={$_.Threads.Count}}, @{N='MB';E={[math]::Round($_.WorkingSet64/1MB,2)}}
```

预期：默认 1 worker = 5 线程 / 约 5.4 MB；`--threads 2` = 6 线程 / 约 5.4 MB。

## 九、清理

```bash
rm -rf run-* ro bare            # harness 生成的临时目录
taskkill /F /IM sms.exe         # 兜底：结束所有遗留服务进程
```

压测产生的大量写请求会让 CPU 占满（8 客户端 + 服务端同机），
跑压测时不要同时做其他事，数字才稳。
